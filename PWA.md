# PWA Guide — Hisab

Hisab is a Progressive Web App (PWA) that can be installed on iOS, Android, and desktop browsers. It works fully offline after initial caching and stores all data locally in IndexedDB.

## PWA Capabilities

### Installable

- **iOS/iOS:** Add to Home Screen via the browser share sheet. Runs in standalone mode with a custom status bar.
- **Android:** Install via the browser's "Add to home screen" prompt. Runs as a standalone app.
- **Desktop:** Installable on Chromium and Edge browsers.

### Offline-First

- The service worker caches all app assets (JS, CSS, HTML, images, fonts) on first load via Workbox.
- All financial data lives in IndexedDB (Dexie), which is persistent and local.
- No network requests are required for core features after initial caching.

### Platform Integration

- **Home screen icon:** 192x192 and 512x192 PNG icons, plus a maskable variant for adaptive theming.
- **Splash screens:** Generated by `vite-plugin-pwa` from the PWA assets config.
- **Status bar:** Custom `theme-color` (#0E7C5A) and `apple-mobile-web-app-status-bar-style: black-translucent`.
- **Safe area insets:** The app uses `env(safe-area-inset-*)` for notch/dynamic island handling.

## Manifest Configuration

The PWA manifest is defined in `vite.config.js` under `VitePWA({ manifest: { ... } })`:

| Field              | Value                         | Purpose                  |
| ------------------ | ----------------------------- | ------------------------ |
| `name`             | "Hisab — Personal Finance"    | Full app name            |
| `short_name`       | "Hisab"                       | Home screen label        |
| `display`          | `standalone`                  | Hides browser chrome     |
| `orientation`      | `portrait`                    | Phone-first layout       |
| `theme_color`      | `#0E7C5A`                     | Brand green              |
| `background_color` | `#EEF2F0`                     | Splash screen background |
| `categories`       | `["finance", "productivity"]` | App store categorization |
| `scope`            | `/`                           | Full-site scope          |

## Service Worker

Configured via `vite-plugin-pwa` with `registerType: "autoUpdate"`:

- **Caching strategy:** Workbox glob pattern `**/*.{js,css,html,svg,png,ico,woff2}` caches all static assets.
- **Auto-update:** The service worker updates silently in the background when a new version is deployed.
- **Cleanup:** `cleanupOutdatedCaches: true` removes stale caches on each activation.
- **Dev mode:** `devOptions.enabled: true` allows testing the SW during development.

## Deployment

### Vercel

The `vercel.json` file configures Vercel deployment:

```json
{
  "rewrites": [
    {
      "source": "/.well-known/assetlinks.json",
      "destination": "/assetlinks.json"
    },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

- `assetlinks.json` is served for Android app linking verification.
- All other routes fall back to `index.html` (SPA routing).

### Build

```bash
npm run build
```

The build output goes to `dist/`. The PWA assets generator (`pwa-assets-generator`) creates icons, splash screens, and the `service-worker.js` file.

## Regenerating Icons

```bash
npm run generate:icons
```

This runs `@vite-pwa/assets-generator` which generates all icon sizes, maskable variants, and splash screens from the source assets in `public/`.

## Security Context

Web Crypto API (PBKDF2, AES-GCM) requires a **secure context** — HTTPS or localhost. When testing on a physical device:

- Use a tunnel (Cloudflare Tunnel, ngrok, etc.) to expose localhost over HTTPS.
- Or deploy to a HTTPS host (Vercel, Netlify, etc.).

The `src/lib/webcrypto.js` module handles this with `requireCrypto()` which throws `InsecureContextError` if `crypto.subtle` is unavailable.

## Offline Behavior

After initial load, the app is fully functional offline:

- **Dashboard:** Shows cached balances and recent transactions.
- **Accounts/Categories:** Read from IndexedDB.
- **Transactions:** Read/write to IndexedDB.
- **Import/Export:** Operates on local files and IndexedDB.
- **Backup/Restore:** Works entirely locally.

Only the Google Fonts CDN request requires connectivity on first load. The font is cached by the service worker on first successful fetch.
